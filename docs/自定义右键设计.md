# 自定义右键菜单设计（2026-11-25，第三版）

> 分支：`feature/context-menu`（从 `master` 起，不改 master、不改原功能分支）
>
> 目标：管理本程序自己的右键菜单，并把系统右键里的第三方功能按「应用 + 经典/现代」
> 以动态组的形式挂进来。**设置里平铺勾选，右键里同名动态组，不合并、不显示括号。**

---

## 1. 已拍板的规则

1. 第三方只做**动态组**：配置里只存“哪个应用、经典还是现代”，不存功能项、不存扩展名。
2. 设置列表按「应用 + 来源类型」平铺：
   - `WPS Office（经典）`
   - `WPS Office（现代）`
   - `7-Zip（经典）`
   - `TortoiseSVN（经典）` / `TortoiseSVN（现代）`
   - 默认**不勾选**。
3. 设置里**不展开二级菜单、不预览功能**。要展开就得按扩展名普查，这是明确要避免的。
4. 右键菜单里只显示应用名，**不显示（经典）/（现代）**。
5. 如果经典和现代都勾了，右键菜单里就是**两个同名的应用条目**，各自装各自的功能；
   **不合并**、不去重。
6. 某条来源在当前扩展名下没有功能时，展开后显示灰色「此扩展名无可用功能」；
   不在主菜单构建阶段预先采集（保持右键弹出快）。
7. 删除只删「添加程序…」手动加的程序；第三方靠取消勾选。
8. 恢复默认 = 内置项回默认 + 第三方全部取消勾选 + 手动程序保留。

## 3. 数据

文件：`%APPDATA%\FileExplorer\context-menu.json`

```json
{
  "version": 1,
  "scenes": {
    "file": ["open", "openWith", "sep", "...", "actions", "sep", "properties"]
  },
  "thirdParty": {
    "file": [
      { "key": "WPS Office|0", "app": "WPS Office", "source": "classic" },
      { "key": "WPS Office|1", "app": "WPS Office", "source": "modern" }
    ]
  },
  "aliases": {
    "builtin:open": "打开文件",
    "third:WPS Office|0": "WPS 经典"
  },
  "actions": [
    {
      "id": "a1",
      "title": "用 Notepad3 打开",
      "program": "C:\\Tools\\Notepad3.exe",
      "arguments": "%1",
      "startIn": "%dir%",
      "scenes": ["file", "folder", "multiple"],
      "enabled": true,
      "order": 10
    }
  ]
}
```

- `scenes`：内置项顺序/显隐；`actions` 是第三/手动块的插入标记。
- `thirdParty`：每个场景勾选的「应用 + 来源」；`key = 应用名 + "|" + 0/1`。
- `actions`：手动添加的程序，平铺菜单项。
- 配置缺失/损坏回默认；保存用临时文件 + 替换，旧文件留 `.bak`。

## 4. 应用归组（owner → 应用 + 经典/现代）

原始 owner 缓存（`menu-owners.json`）是**一个 handler 一条**，不能直接当应用列表。
新增 `shell/MenuApps` 归组层：

- 只取 `probeStatus == ok` 的 `ShellHandler` / `PackagedCommand`。
- 过滤 `%SystemRoot%` 下的系统 handler（保留 WindowsApps 里的 Windows Terminal/照片等）。
- 过滤 `ms-resource:` 这类没解析出来的系统显示名。
- 应用名：
  - 经典 handler：DLL 版本资源的 `ProductName`，退回 `CompanyName`/`FileDescription`/文件名。
  - 现代包：`AppxManifest.xml` 的 `PublisherDisplayName`/`DisplayName`。
  - 现代包按发布者与经典应用的公司做归一化匹配（WPS 的 Kingsoft ↔ 珠海金山），
    归到同一个应用名；归不到就用自己的名字。
- 结果：`AppSourceRow { appName, source(经典/现代), scenes, owners[] }`。
  - 一个来源类型下多个 handler（如 WPS 经典有多个 DLL）合并到这一条；
  - **不同来源类型绝不合并**。

在你这台机器上的归组结果（实测日志）：WPS Office（经典）、WPS Office（现代）、
7-Zip、TortoiseSVN（经典/现代）、WinRAR、ChatGPT、PDFToolExtension、ima_context_menu 等。

## 5. 运行时

- 主右键菜单构建时，只给每个勾选的第三方行创建一个**空壳子菜单** + 「正在读取…」，
  并记住 owner 列表、当前选中路径、父目录、场景。
- 用户展开子菜单（`WM_INITMENUPOPUP`）时，才对该行的每个 owner 调
  `CaptureOwnerMenu`（经典 `IContextMenu` / 现代 `IExplorerCommand`），
  把菜单项树渲染进子菜单；每个叶子项分配独立命令号段（3800+），点击时
  `InvokeInventoryItem` 回放。
- 同一行有多个 owner 时按顺序追加，中间加分隔线；全部为空就显示灰色提示。
- 图标：采集时落盘到 `%APPDATA%\FileExplorer\menu-icons`，菜单用
  `MenuIconCache::GetFile` 取；一级应用图标用 `GetOwnerIcon`。
- 不预采功能项、不存扩展名矩阵；扩展名完全由 handler 自己判断。

## 8. v1 边界

- 只做动态组，不做静态命令（某些软件的「用 X 打开」不单独列；需要时用「添加程序…」）。
- 某来源没有对应扩展名功能时，条目会出现但展开为灰色提示；不预先隐藏。
- 应用归组靠版本资源/包发布者；归不到的应用名可能不好看（如 `ima_context_menu`），
  可以在设置里双击「右键显示名」改别名。
- 现代包在非 Explorer 进程里个别会失败；失败记日志，不影响其它应用。
- **空功能隐藏还没做**：当前展开后显示灰色「此扩展名无可用功能」；按用户要求，
  等拍平/经典来源/别名完成后再做采集缓存。

## 9. 2026-11-26 追加

### 9.1 拍平/合并

- 2级里同名目录先合并子项；
- 合并后数“目录”（有子项的项），不数叶子；
- 只剩一个目录且名字和1级一样 → 去掉2级，子项直接挂1级（叶子保留）；
- 只剩一个目录但名字不同 → 1级名字改成 `1级 · 2级`，子项直接挂1级；
- 多个不同目录 → 保留。

`src/shell/MenuFlatten.cpp` 实现，`MenuFlattenTest` 覆盖。

### 9.2 经典来源探测

WinRAR 7.x 只注册 PackagedCom 现代菜单，但同一个 CLSID/DLL 仍实现经典
`IContextMenu`。`EnsureClassicFallbacks` 在第一次打开设置时，对没有经典来源的
现代 owner 用同一 CLSID 做一次经典能力探测；成功就补一条 `ShellHandler` owner
（`shellex:{clsid}`），失败/已有经典来源就记 `classicProbe` 后跳过。
不写注册表，结果写回 `menu-owners.json`，不会每次开设置重试。

### 9.3 别名

- 设置列表第三列「右键显示名」，显示实际会出现在右键上的名字；
- 双击行或「改名…」按钮 → 原地编辑；回车提交、Esc 取消、清空恢复默认；
- 别名按 `builtin:<id>` / `third:<appKey>` / `manual:<id>` 全局保存；
- 右键渲染优先用别名，不显示（经典）/（现代）。

### 9.4 分隔线

- 修 `MenuLayout::NormalizeMenuOrder`：`sep` 是位置标记，允许重复；之前用
  `std::set seen` 把第二个以后的分隔线在加载时就吃掉了；
- 设置窗口加「加分隔线」按钮；「删除」也允许删除分隔线；
- 保存只折叠连续/首尾分隔线，不误删中间的分隔线。
