# 自定义右键菜单设计（2026-11-25）

> 分支：`feature/context-menu`（从 `master` 起）
> 目标：让用户自定义**本程序自己的右键菜单**，而不是去镜像/重组 Windows 或第三方软件的菜单。

---

## 1. 一句话

**右键菜单 = 本程序内置项（可勾选、可排序）+ 用户自己的快捷动作。**

不采集系统右键菜单、不调第三方 Shell 扩展、不做「系统菜单」兜底入口。

---

## 2. 为什么不再走「采集 + 重组」那条路

旧方案（`MenuCensus` / `MenuInventory` / `MenuConfig` / 4,440 行配置窗口）做的是：

1. 把系统右键菜单采集进来；
2. 按应用 / handler / 场景 / 扩展名归类；
3. 用户拖拽成自己的分组；
4. 点击时按保存的 handler / command offset 回放。

它改不到满意的原因不是实现细节，而是方向本身没有收敛点：

- 系统菜单是运行时产物：装软件、升级、Win11 现代菜单、不同场景都会变，永远有下一个 case；
- 用户配置的是「别人菜单项的身份」，不是「我要什么」，认知负担大、结果难预期；
- COM、注册表、包身份、菜单位图都进了主链路，任何一环异常都要动核心；
- 没有稳定的「配置 → 菜单」契约，只能人工点，越改越不敢动。

旧方案在功能分支上新增了 **12,883 行**，用户拿到的仍然只是「别人菜单的副本」。本设计明确不再走这条路。

---

## 3. 结构

### 3.1 内置项：勾选 + 排序

每个场景（文件夹空白处 / 单选文件 / 单选文件夹 / 多选）有一份**有序清单**：

- 在清单里 = 显示；不在 = 隐藏；
- 顺序就是菜单顺序；
- `sep` = 分隔线；`actions` = 快捷动作整组；
- 构建时先算出「这次哪些项可用」（粘贴要有剪贴板、撤销要有栈、打开方式要有账本…），再按配置顺序渲染；
- 不可用项跳过，连续/首尾分隔线自动收掉。

**默认清单和改造前的菜单逐项一致**，不配置时行为零变化。

### 3.2 快捷动作：用户自己的程序

一条动作 = **程序 + 参数模板 + 适用场景 + 扩展名**。

- 添加程序：文件选择框，自动填「用 XXX 打开」、`%1`、`%dir%`；
- 预设：VS Code / 7-Zip 解压 / WinRAR 解压 / PowerShell / 记事本（检测到才出现）；
- 不需要用户写命令行；高级字段（参数模板）仍保留在 JSON 里，给愿意折腾的人。

### 3.3 明确不做

- 不采集、不镜像、不调用第三方 Shell 扩展的右键菜单；
- 不做「系统菜单…」兜底入口（2026-11-25 用户明确否决）；
- 不写注册表、不改文件关联；
- 不做菜单配色 / 字体 / 宽度；
- 不做应用归属、动态组、菜单项普查；
- 盘符/虚拟项、压缩包内部、左栏菜单保持现有固定菜单，不参与自定义。

> 第三方软件的复杂右键菜单（WPS 转换、WinRAR 的十几个子项等）不在本功能范围内。
> 需要某个具体程序时，用「添加程序…」或预设；程序自己没有内置替代的复杂功能，不承诺复刻。

## 4. 数据

文件：`%APPDATA%\FileExplorer\context-menu.json`（独立于 `settings.json`，方便备份/导入导出）。

```json
{
  "version": 1,
  "scenes": {
    "background": ["view", "sort", "refresh", "sep", "paste", "sep",
                   "undo", "redo", "sep", "newFolder", "new", "sep",
                   "terminal", "sep", "actions", "sep", "properties"],
    "file": ["open", "openInNewWindow", "openWith", "sep",
             "cut", "copy", "copyPath", "sep", "undo", "redo", "sep",
             "delete", "sep", "rename", "sep", "actions", "sep", "properties"],
    "folder": ["open", "openInNewWindow", "sep", "cut", "copy", "copyPath", "sep",
               "undo", "redo", "sep", "delete", "sep", "rename", "sep",
               "terminal", "sep", "actions", "sep", "properties"],
    "multiple": ["open", "sep", "cut", "copy", "copyPath", "sep",
                 "undo", "redo", "sep", "delete", "sep", "batchRename", "sep",
                 "actions", "sep", "properties"]
  },
  "actions": [
    {
      "id": "a1",
      "title": "用 VS Code 打开",
      "program": "C:\\Users\\me\\AppData\\Local\\Programs\\Microsoft VS Code\\Code.exe",
      "arguments": "%1",
      "startIn": "%dir%",
      "icon": "",
      "scenes": ["file", "folder", "multiple"],
      "extensions": [],
      "enabled": true,
      "runAsAdmin": false,
      "order": 10
    }
  ]
}
```

### 4.1 内置项 ID

| 场景 | ID |
|---|---|
| 空白处 | `view` `sort` `refresh` `paste` `newFolder` `new` `terminal` `undo` `redo` `properties` `actions` |
| 单选文件 | `open` `openInNewWindow` `openWith` `cut` `copy` `copyPath` `delete` `rename` `undo` `redo` `properties` `actions` |
| 单选文件夹 | `open` `openInNewWindow` `cut` `copy` `copyPath` `delete` `rename` `terminal` `undo` `redo` `properties` `actions` |
| 多选 | `open` `cut` `copy` `copyPath` `delete` `batchRename` `undo` `redo` `properties` `actions` |

- `undo` / `redo` 是两项（不是一项），文案随撤销栈动态变化；
- `openWith` 只在账本里有该扩展名的程序时可用；
- `openInNewWindow` 在文件场景只对压缩包文件可用；
- `paste` / `terminal` 在压缩包内部不可用；
- `cut` / `delete` 在「主文件夹」的系统入口上不可用。

### 4.2 读写规则

- 启动/首次右键读一次，内存缓存；配置窗口保存后失效，下次右键重新读。
- JSON 解析失败：留一份 `.bad`，回默认布局，记日志，不崩。
- 保存：临时文件 + `MoveFileEx` 替换；旧文件留 `.bak`。
- 未知 ID、重复 ID、不属于该场景的 ID 自动丢弃；某个场景写了内容但全是非法项时回默认。
- 场景清单为空 = 该场景全隐藏；但四个场景全空时配置窗口会拦住，避免右键菜单变白。

## 5. 快捷动作的执行

### 5.1 占位符

| 占位符 | 含义 | 自动加引号 |
|---|---|---|
| `%1` | 第一个选中项；空白区 = 当前目录 | 是 |
| `%sel%` | 全部选中项；空白区 = 当前目录 | 每个都加 |
| `%dir%` | 当前文件夹 | 是 |

- 占位符外面再包一层双引号（`"%1"`）也兼容，不会变成 `""路径""`；
- 只做一遍替换，路径里出现 `%` 不会被二次展开；
- 未知占位符原样保留。

### 5.2 多选

- 参数里有 `%sel%` → 启动一次，带全部路径；
- 只有 `%1` → 每个路径启动一次；
- 两个都没有 → 启动一次，不带路径；
- 扩展名过滤只对文件/多选生效；多选要求**所有**选中项都匹配。

### 5.3 启动方式

| 程序类型 | 方式 |
|---|---|
| `.exe` | `CreateProcessW`，程序和参数分开传 |
| `.bat` / `.cmd` | `cmd.exe /d /s /c` |
| `.ps1` | `powershell.exe -NoProfile -ExecutionPolicy Bypass -File` |
| `.lnk` / 文档 / 其它 | `ShellExecuteExW` |
| 管理员 | `ShellExecuteExW` + `runas` |

- 程序与参数分开两个字段，不解析整条命令行；
- 路径按 `CommandLineToArgvW` 规则加引号（空格、反斜杠、引号都测过）；
- 程序不存在：不静默消失，启动失败记日志 + 可选提示；
- 启动成功记 `info`（动作名 + PID），失败记 `warn`。

## 6. 界面

入口：设置 → 「自定义右键菜单…」。

```
┌ 自定义右键菜单 ───────────────────────────────────────────────┐
│ 场景 [单选文件 ▾]   勾选要显示的项；列表顺序就是菜单顺序       │
├────────────────────────────────┬───────────────────────────────┤
│ ☑ 打开                         │ 快捷动作（可选）              │
│ ☑ 打开方式                     │  用 VS Code 打开              │
│ ──────── 分隔线 ────────       │  7-Zip 解压到当前文件夹        │
│ ☑ 剪切 / 复制 / 复制文件路径    │                               │
│ ☑ 撤销 / 恢复                  │ [添加程序…] [预设 ▾] [删除]   │
│ ...                            │ [上移] [下移]                 │
├────────────────────────────────┴───────────────────────────────┤
│ [上移] [下移] [加分隔线] [恢复默认]           [保存] [取消]   │
└────────────────────────────────────────────────────────────────┘
```

- 列表里始终列出该场景的**全部**内置项；不勾选 = 隐藏，之后还能改回来；
- 分隔线是一行，可勾选、取消、移动；连续分隔线保存时合并；
- 「快捷动作」是整组开关，具体动作在右栏添加/删除/排序；
- 保存后立即生效，不用重启。

---

## 7. 性能

- 右键弹出只读内存配置 + 预取好的图标缓存，不读注册表、不调 COM、不探测文件；
- 快捷动作图标在后台线程取（`MenuIconCache::PrefetchPaths`），弹出时只查表；没取到就留空；
- 带环境变量的程序路径不预取图标（避免每次弹出重试）。

## 8. 测试

- `tests/MenuLayoutTest.cpp` + `tools/run-menu-layout-tests.ps1`：
  - 四个场景的默认顺序与改造前逐项一致；
  - 隐藏项后分隔线折叠/首尾清理；
  - 动作组出现/消失；
  - JSON 往返、坏配置回退、未知 ID 丢弃、动作字段清洗。
- `tests/ActionRunnerTest.cpp` + `tools/run-action-tests.ps1`：
  - 引号（空格 / 反斜杠 / 引号 / 空串）；
  - `%1` / `%sel%` / `%dir%` 展开、多选一组/多组、不递归；
  - 场景/扩展名匹配；
  - 用 `cmd.exe` 真实跑一次，验证带空格路径能原样传进去；程序不存在时报错。
- 实机：设置窗口打开配置、保存后右键菜单按新顺序/显隐出现；快捷动作点击执行；图标开关打开时显示程序图标。

## 10. 以后可选（不包含兜底入口）

- 动作级图标选择（现在默认用程序图标）；
- 每个动作单独指定子菜单（现在只有一个「快捷动作」整组）；
- 导入/导出按钮（JSON 现在可以直接备份）；
- 内置项的「仅显示我勾选的」之外，增加分组标题（不是必须）。

**不恢复**：系统菜单采集、第三方 Shell 扩展回放、系统菜单兜底入口。
