### 左侧导航栏的设计取舍（已与你确认：选 B 方案）

- **只做两层**：快速访问（桌面/下载/文档/图片/音乐）+ 此电脑（各硬盘）
- **不做展开**：点硬盘直接跳到根目录，不能点开看它的子文件夹
- **不做的原因**：可展开树是这块最费工的部分（每展开一层都要重新枚举目录 + 记住展开状态）
- 左栏宽度 240（按 DPI 缩放），窗口太窄时自动收起左栏
- 图标全部来自系统，桌面/下载是各自真实图标，硬盘是系统硬盘图标

### 阶段 3.6：外观修正（用户反馈「文件夹图标和导航条样式不对」）

**问题 1：文件夹全显示成硬盘图标**

原因：取文件夹图标时样本路径写的是 `C:\`，Shell 把它识别成驱动器。
修复：样本改成 `"folder"`。详见踩坑记录「坑 6」。

**问题 2：顶部三个按钮是系统标准按钮，带灰色立体边框**

原因：`BUTTON` 控件外观由系统主题绘制，没法做成 Windows 11 那种无边框扁平样。
修复：新增 `src/ui/FlatButton.*` 自绘按钮，平时只画箭头，悬停浅灰圆角底，
按下深一点，禁用箭头变灰。箭头用线段画，不用图标字体（避免边缘发毛）。详见踩坑记录「坑 7」。

**顺带改的两处**

- 地址栏边框从 `WS_EX_CLIENTEDGE`（2px 立体边）改为 `WS_EX_STATICEDGE`（1px 细边）
- 导航栏「快速访问」分组图标改用 `IconCache::FolderIconIndex()`，不再走 `C:\` 取图标

### 阶段 5：文件操作改后台执行 + 右键菜单

**一、大文件复制不再卡界面**

原来粘贴/删除是在界面线程里等系统搬完，复制 1G 文件的那几秒钟整个窗口不能操作。
现在把整个操作放到一条后台线程里跑：

- 后台线程自己初始化 COM（每个线程独立，不能借用主线程的）
- 系统进度框照样弹，点「取消」照样管用
- 操作结束后线程往主窗口发一条消息，主窗口重新扫当前目录刷新
- 同一时间只允许一个文件操作，避免两个进度框打架
- 关闭窗口时会等后台操作收尾（用户也可以在进度框里点取消让它提前结束）

**实测数据**（复制 1GB 文件到子目录，C 盘内）：

| 指标 | 结果 |
|---|---|
| 复制耗时 | 2.9 秒（1GB） |
| 复制期间主窗口响应 | 每次探测 1～20 ms，**没有一次卡住** |
| 完成后 | 自动刷新，列表显示 1 项 ✅ |

> 对照：改造前同样的探测会超时（主窗口被同步调用占住）。

**二、右键菜单**

在文件列表上按右键弹出，和资源管理器同样的位置、同样的操作：

```
打开
────────────────
复制

粘贴      ← 剪贴板空时变灰

────────────────
```

没选中文件时，「打开/复制/剪切/删除」变灰；剪贴板空时「粘贴」变灰。
「属性」弹的是 Windows 原生的属性窗口（这个窗口不是我们画的，系统自带）。
「打开」和双击效果一样：文件夹进去，文件用默认程序打开。

### 阶段 6：表头排序、F2 重命名、刷新不再整屏重建

**一、点表头排序**

点「名称 / 修改日期 / 类型 / 大小」任意一列表头，就按那列排：

- 第一次点 = 升序（小到大），再点同一列 = 降序，交替
- 换一列就从升序开始
- 表头上会有系统自带的小三角箭头 ▲ / ▼，不用自己画
- **文件夹永远排在最前面**，这条不受点哪一列影响（和资源管理器一致）
- 排序后滚动位置和选中项都保留

**二、F2 重命名**

选中一项按 F2（或在右键菜单里点「重命名」），名字原地变成可编辑框：

- 直接改，回车确认，Esc 取消
- 名字没变就不做任何操作
- 名字里有 `\ / : * ? " < > |` 这些非法字符，自己先挡掉，不弹系统的英文报错框
- 改名成功后只更新这一行，不重扫目录
- 和系统一样的冲突处理（目标已存在同名会弹系统的询问框）

**三、删掉「整屏刷新」这个毛病**

原来的做法：删除/新建之后，把整个目录重新枚举一遍，然后清空列表重新填，
结果就是**选中丢了、滚动位置回到顶部、屏幕闪一下**。

现在的做法分两种：

| 操作 | 以前 | 现在 |
|---|---|---|
| 删除 | 重扫整个目录 + 重建列表 | **直接从列表里摘掉删掉的那几行**，0 毫秒，不闪 |
| 新建文件夹 | 重扫整个目录 + 重建列表 | **往列表里插一行**并选中它，0 毫秒，不闪 |
| 复制/移动粘贴 | 重扫整个目录 + 重建列表 | 仍要重扫（新增多少项、名字会不会变成「xxx - 副本」事先不知道），但**保留滚动位置和选中项，且不擦背景不闪白** |

重扫时保留状态的实现：刷新前记下「选中了哪些名字」「顶部是哪一行」，
数据换完之后按名字把它们找回来，所以用户不会感觉列表被"重置"了。
