### ① 主文件夹 / 控制面板 / 回收站等系统项图标显示成黄色文件夹

- 原因：`SHGetFileInfo` 的**字符串**接口不认 `::{GUID}` 这种系统节点名，一律返回 0；
  代码又把 0 当成"没取到"，退回普通文件夹图标。详见踩坑记录「坑 25」。
- 修法：`ShellIcon.cpp` 的 `GetIconIndexByFullPath` 里判 `::` / `shell:` 前缀，
  先用 `SHParseDisplayName` 换成 PIDL，再用 `SHGFI_PIDL | SHGFI_SYSICONINDEX | SHGFI_SMALLICON` 查，
  结果照旧写 `m_pathIconCache`。
- 实测 iIcon：主文件夹 72 / 控制面板 21 / 回收站 32 / 网络 17 / 此电脑 15 / 桌面 74 / 库 295。

### ② 控制面板里的项双击打不开功能

- 原因：这些项（BitLocker、恢复、安全和维护、凭据管理器…）属性上带 `SFGAO_FOLDER`，
  程序当成文件夹往里导航，而它们其实是 applet，进去只有一个空列表。
- 修法：新增 `shell::ShellItemIsContainer()`，探测它能不能真的绑定出 `IShellFolder` 并 `EnumObjects`；
  `MainWnd::OnItemActivated` 里：容器 → 导航（空目录也进），非容器 → 交给系统打开。
  详见踩坑记录「坑 26」。
- 实测：双击 BitLocker → 弹出系统界面；回收站 → 进入 647 项；控制面板 9 项 → 所有控制面板项 39 项。

### ③ 程序 exe 和标题栏没有图标

- 新增 `res/app.ico`（16/32/48/256 四尺寸 PNG-in-ICO）、`res/resource.h`（`IDI_APPICON 101`）；
  `res/app.rc` 加 `IDI_APPICON ICON "app.ico"`；`MainWnd.cpp` 窗口类的 `hIcon` / `hIconSm` 改用它，
  取不到才退回 `IDI_APPLICATION`。
- 实测：exe 文件图标、标题栏左上角、任务栏都显示新图标。

### ④ 顺带修：回收站等顶层项的「向上」落到了物理桌面

- 回收站的系统父项是 `C:\Users\kf168\Desktop`（物理桌面目录），点向上会掉进"只有桌面文件"的 33 项；
  资源管理器里应该回到那个装着「此电脑/主文件夹/音乐…」的「桌面」容器（51 项）。
- 修法：`ShellFolder.cpp` 新增 `IsPhysicalDesktopPath()`，`GetParentPath()` 里把物理桌面换成顶层容器伪路径。
  详见踩坑记录「坑 27」。

### 阶段 5：文件操作改后台执行 + 右键菜单

**一、大文件复制不再卡界面**

原来粘贴/删除是在界面线程里等系统搬完，复制 1G 文件的那几秒钟整个窗口不能操作。
现在把整个操作放到一条后台线程里跑：

- 后台线程自己初始化 COM（每个线程独立，不能借用主线程的）
- 系统进度框照样弹，点「取消」照样管用
- 操作结束后线程往主窗口发一条消息，主窗口重新扫当前目录刷新
- 同一时间只允许一个文件操作，避免两个进度框打架
- 关闭窗口时会等后台操作收尾（用户也可以在进度框里点取消让它提前结束）

**实测数据**（复制 1GB 文件到子目录，C 盘内）：

| 指标 | 结果 |
|---|---|
| 复制耗时 | 2.9 秒（1GB） |
| 复制期间主窗口响应 | 每次探测 1～20 ms，**没有一次卡住** |
| 完成后 | 自动刷新，列表显示 1 项 ✅ |

> 对照：改造前同样的探测会超时（主窗口被同步调用占住）。

**二、右键菜单**

在文件列表上按右键弹出，和资源管理器同样的位置、同样的操作：

### 阶段 6：表头排序、F2 重命名、刷新不再整屏重建

**一、点表头排序**

点「名称 / 修改日期 / 类型 / 大小」任意一列表头，就按那列排：

- 第一次点 = 升序（小到大），再点同一列 = 降序，交替
- 换一列就从升序开始
- 表头上会有系统自带的小三角箭头 ▲ / ▼，不用自己画
- **文件夹永远排在最前面**，这条不受点哪一列影响（和资源管理器一致）
- 排序后滚动位置和选中项都保留

**二、F2 重命名**

选中一项按 F2（或在右键菜单里点「重命名」），名字原地变成可编辑框：

- 直接改，回车确认，Esc 取消
- 名字没变就不做任何操作
- 名字里有 `\ / : * ? " < > |` 这些非法字符，自己先挡掉，不弹系统的英文报错框
- 改名成功后只更新这一行，不重扫目录
- 和系统一样的冲突处理（目标已存在同名会弹系统的询问框）

**三、删掉「整屏刷新」这个毛病**

原来的做法：删除/新建之后，把整个目录重新枚举一遍，然后清空列表重新填，
结果就是**选中丢了、滚动位置回到顶部、屏幕闪一下**。

现在的做法分两种：

| 操作 | 以前 | 现在 |
|---|---|---|
| 删除 | 重扫整个目录 + 重建列表 | **直接从列表里摘掉删掉的那几行**，0 毫秒，不闪 |
| 新建文件夹 | 重扫整个目录 + 重建列表 | **往列表里插一行**并选中它，0 毫秒，不闪 |
| 复制/移动粘贴 | 重扫整个目录 + 重建列表 | 仍要重扫（新增多少项、名字会不会变成「xxx - 副本」事先不知道），但**保留滚动位置和选中项，且不擦背景不闪白** |

重扫时保留状态的实现：刷新前记下「选中了哪些名字」「顶部是哪一行」，
数据换完之后按名字把它们找回来，所以用户不会感觉列表被"重置"了。

### 阶段 7：剪贴板与系统互通

**原来什么毛病**：剪贴板只记在自己程序内存里。
从资源管理器复制的文件，在本程序按 Ctrl+V 粘不进来；
在本程序复制的文件，到资源管理器里也粘不出来。

**现在怎么做**：改用 Windows 的标准剪贴板格式。

| 格式 | 作用 |
|---|---|
| `CF_HDROP` | 一堆文件路径。资源管理器、桌面、别的程序都认这个格式 |
| `Preferred DropEffect` | 一个数字：1 = 复制，2 = 剪切。没有它接收方一律当复制处理，Ctrl+X 就失效 |

- Ctrl+C 往剪贴板写 `CF_HDROP` + 效果 1（复制）
- Ctrl+X 往剪贴板写 `CF_HDROP` + 效果 2（剪切）
- Ctrl+V **每次都从系统剪贴板读**（不是读自己内存里记的），所以从哪儿复制来的都能粘
- 剪切粘贴成功后把剪贴板清空（和资源管理器行为一致）

**几个容易翻车的细节**：

1. `SetClipboardData` 成功之后，那块内存就归系统了，**绝对不能再 `GlobalFree`**，
   否则程序直接崩。只有失败时才需要自己释放。
2. `GetClipboardData` 拿到的内存只有到 `CloseClipboard` 之前有效，
   所有字符串必须在关闭剪贴板之前复制出来。
3. 剪贴板同一时间只能被一个程序占用，遇到占用要重试（我们重试 10 次，每次隔 50ms）。

**问题 2：文件被剪切走了，源目录还显示着它**

移动完成后遍历本次操作涉及的路径，凡是父目录等于当前目录的，直接从列表里摘掉

这条属于保险性修复，一并做了。

**问题 3：删除、复制会整表刷新，新建文件夹又不刷新——统一成"不整表刷新"**

核心是 `FileListView::MergeResult`：拿到新枚举结果后，逐行比对 `fullPath`，
找到第一个不同的位置 `common`：

- 全等 → 直接返回，一个像素都不重绘
- 有差异 → `SetItemCountEx` 新数量 → 还原选中和滚动 → `ListView_RedrawItems(common, count-1)`

另外两处必须同时改，否则会"先空再满"：

1. `StartEnumeration` 不再无条件 `SetResult(nullptr)`，只有**目标目录 ≠ 当前显示目录**时才清空
2. `RestoreSelectionAndScroll` 先 `LVM_SETITEMSTATE(-1, 0)` 清空所有选中再按名字恢复
   （否则"选中的行号"会粘到新内容上，等于选错了东西）

粘贴完成后用 `AllPaths()` 求差集 + `SelectPaths()` 把新出现的项选中，和资源管理器一致。

`OnEnumerationDone` 和 `OnColumnClick` 都改成走 `MergeResult`。

### 阶段 9.5：拖到子文件夹 + 外部改动自动刷新（你提的两个问题）

**问题 1：拖到列表里"新建文件夹"这种文件夹上没反应**

原来列表的落点永远是"当前目录"，拖到文件夹图标上也不会进那个文件夹。

改成两级判断：

1. 鼠标压在这一行上（整行都算，压在其他列上也认），**且这一行是文件夹** →
   落点 = 这个文件夹的完整路径
2. 压在文件行上 / 压空白处 → 落点 = 当前目录

视觉反馈：用系统自带的拖放高亮（`LVIS_DROPHILITED`）把鼠标正压着的那一行点亮，
和资源管理器一致；鼠标离开列表或放完自动清掉。

**问题 2：文件被移走 / 删除后列表不自己更新（本程序内部、资源管理器外部都不刷）**

根因：以前只有"本程序自己做文件操作"结束时才刷新一次，
别的程序动过的文件，本程序完全不知道。

新增 `src/core/FolderWatcher.*`：用系统的 `ReadDirectoryChangesW`
盯着当前目录，一有变化就通知主窗口。

三道保护，保证它不会拖慢速度、也不会打断用户：

| 保护 | 做法 | 解决什么 |
|---|---|---|
| 独立线程等待 | 监视放后台线程，没变化时完全睡着，不占 CPU | 不在界面线程做阻塞调用，窗口不卡 |
| 通知合并（防抖） | 收到通知只排一个 250ms 定时器，反复重置；动静停了才真正刷一次 | 批量复制一万个文件时不会把界面刷成幻灯片 |
| 冲突退让 | 文件操作进行中 / 正在 F2 改名，这一轮直接跳过 | 刷新不会打断正在进行的操作和输入 |

刷新本身走的是已有的**差异更新**路径（`MergeResult`），
只重绘真正变了的那几行，不会整表重建。

### 3. 控制面板项双击打不开（已修复，实测通过）

   都回 `E_INVALIDARG(0x80070057)`。

改法：**把枚举时的绝对 PIDL 存进 ShellEntry**（纯字节，不含 COM 指针，符合跨线程约定），
打开时用 `ShellExecuteExW` + `SEE_MASK_IDLIST | SEE_MASK_INVOKEIDLIST` 执行默认动词。
- `ShellEntry` 新增 `std::vector<unsigned char> pidl`，只在 Shell 命名空间目录里填
  （物理目录的条目用 fullPath 就够，省掉每项一次 PIDL 拼接）。
- 新增 `shell::OpenShellItemByPidl(HWND, pidlBytes)`；
  `MainWnd::OnItemActivated` 两个分支都改成「先 PIDL → 再路径字符串 → 最后 ShellExecuteW」。

### 5. 「此电脑」分组（按方案 A 实现，已实测通过）
- 系统里「此电脑」是分组显示的（组名「设备和驱动器」）。列表控件的原生分组

    - `LVN_GETDISPINFO` 对标题行只给名字，`iImage = I_IMAGENONE`；

### 7. 「主文件夹」排序：系统项在前、桌面上的东西在后

现象：主文件夹（顶层桌面，51 项）原来全部按名字混排，

改法：
1. `ShellEntry` 加 `isSystemItem`，枚举时由 `IsDesktopSystemItem` 判定：

2. `CompareEntries` 最前面加一条：`isSystemItem` 不同时，系统项在前。

### 11. 阶段 10：窗口状态持久化（记住上次的样子）

以前每次打开都是"居中 1180x740、左栏 240、默认视图、从 C:\ 开始"，
用起来每次都要重新拖一遍。这一版把这五样记进配置文件，关掉再开还是原样。

记什么（都写在 `%APPDATA%\FileExplorer\settings.json`，和"固定区"同一个文件）：
```json
{
  "window":    { "x": 100, "y": 80, "width": 1000, "height": 700, "maximized": false },
  "paneWidth": 300,
  "columns":   { "time": 160, "type": 120, "size": 110 },
  "view":      { "mode": 0, "manual": true },
  "lastFolder": "C:\\Users\\kf168\\Documents"
}
```
- `window`：还原后的窗口位置与大小，`maximized` 记"关的时候是不是最大化"。
- `paneWidth`：左栏有多宽（拖中间那条竖线得到的值）。
- `columns`：详细信息视图里"修改日期 / 类型 / 大小"三列的宽度（文件名列是自适应的，不用记）。
- `view`：`mode` 是查看模式编号（0 大图标 / 1 小图标 / 2 列表 / 3 详细信息 / 4 平铺），
  `manual` 表示"这是用户从「查看」菜单亲手选的"。只有亲手选过的才一直沿用；
  没选过的话仍然按目录类型自动定（此电脑=平铺，主文件夹=小图标，普通目录=详细信息）。
- `lastFolder`：关窗口时停在哪个目录，下次直接打开它。

什么时候写：
- 关窗口（`WM_CLOSE`）—— 窗口位置大小、当前目录、查看模式；
- 拖完左栏分隔线松手 —— 左栏宽度；
- 拖完表头列宽松手（`HDN_ENDTRACK`）—— 三列宽度。

怎么恢复（`MainWindow::RestoreSavedLayout()`，在 `WM_CREATE` 里调）：
1. 左栏宽度 → 直接设 `m_navWidth`；
2. 三列宽度 → `FileListView::SetFixedColumnWidths(...)`；
3. 查看模式 → 用户选过就先套上，等导航完再按目录规则走。

窗口位置比较特殊：必须**在建窗口之前**读（`Create()` 里 `Settings::Load()`），
按记下来的矩形建窗，否则会先以默认位置开一下再跳。两条保护：
- 记下来的矩形如果已经不在任何显示器上（换了分辨率、拔了外接屏），回居中开窗，并在日志里说明；
- 记下来的目录如果没了（删了、U 盘拔了、虚拟项解析不出来），回 `C:\`，同样写日志。

## 阶段 12（进行中）：打开方式 —— 自研账本，不被任何第三方程序劫持

### 需求口径（用户逐条敲定的）

- 右键「打开方式」二级菜单**只读我们自己的账本**，弹出时零注册表读取、零文件探测。
- 某个扩展名**第一次**双击 / 右键「打开」时弹一次设置窗口，让用户定默认程序，之后固化。
- 账本列表是**快照式**：只在"打开设置窗口"那一刻从系统拉候选，平时不自动更新；
  新出现的程序默认勾选，用户可以取消，取消状态永久保存。
- 商店应用（UWP / 打包桌面应用）必须能打开。
- 默认程序被卸载 → 弹窗让用户重选；菜单里非默认的程序被卸载 → **直接消失，不标灰**。
- 特殊类型（exe / lnk / bat / cmd / msi / scr / ps1 等）和文件夹不接管。

### 只在两个时机读系统（用户明确否决了"右键菜单弹出时探测"）

- C：打开设置窗口时 —— `EnumerateCandidates` + `ProbeAll`，结果写进配置的 `alive` 字段。
- D：真正打开文件时 —— 打开前再 `IsAvailable` 验一次。
- 右键菜单只读内存里的 `alive`：`-1` 未知照常显示、`1` 在、`0` 直接跳过。

### 数据落盘（settings.json 新增 openWith 节点）

```json
"openWith": {
  ".txt": {
    "default": "uwp:Microsoft.WindowsNotepad_8wekyb3d8bbwe!App",
    "items": [
      { "kind": "uwp", "appId": "Microsoft.WindowsNotepad_8wekyb3d8bbwe!App",
        "progId": "AppX4ztfk9wxr86nxmzzq47px0nh0e58b8fw",
        "name": "记事本", "enabled": true, "alive": 1 },
      { "kind": "exe", "path": "C:\\…\\WINWORD.EXE", "args": "", "name": "WINWORD.EXE",
        "enabled": true, "alive": 1 }
    ]
  }
}
```

身份串 `OpenWithKey`：exe 用 towlower 的全路径，商店应用用 `"uwp:" + AUMID`，
勾选状态和默认程序都按这个串比对，程序换版本目录不会张冠李戴。

### 两套启动路径

- **Win32**：`CreateProcessW`，参数按模板拼（先替换带引号的 `"%1"`，再替换裸 `%1`；
  `--single-argument` 系列不加引号且转正斜杠；浏览器家族转正斜杠），工作目录 = exe 目录。
- **商店应用**：`ShellExecuteExW`，`fMask = SEE_MASK_CLASSNAME`，`lpClass = 该 ProgID`。
  系统会按 `HKCR\<ProgID>\shell\open\command` 里登记的 `DelegateExecute` 去激活。
  因为 `lpClass` 是我们自己账本里的 ProgID、不是留空，所以系统"当前默认关联"改成什么
  都影响不到——这仍然是不被劫持的。

### 右键「新建」二级菜单

清单来源和资源管理器一致：`HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\
Discardable\PostSetup\ShellNew` 的 `Classes` 值（REG_MULTI_SZ）给顺序，
每行再去三级注册表视图找模板：

1. `HKCR\<行>\ShellNew`（64 位）
2. `HKCU\Software\Classes\<行>\ShellNew`
3. `HKCR\Wow6432Node\<行>\ShellNew`（32 位程序，如 WinRAR/WPS）

模板类型：`Directory`（文件夹）、`NullFile`/`Data`（空文件）、`FileName`（复制模板）、
`Command`（外部程序自己建，`%1` 换成目标目录）。

本机枚举 15 项，文字与顺序与系统菜单逐字一致：

| 次序 | 显示名 | 键 | 类型 |
| --- | --- | --- | --- |
| 1 | 文件夹 | Folder | Directory |
| 2 | 快捷方式 | .lnk | NullFile+Handler → 系统向导 |
| 3 | BMP 图像 | .bmp | NullFile（系统内置项） |
| 4 | DOC 文档 | .doc | NullFile（注册表已无模板，兜底） |
| 5 | DOCX 文档 | .docx | NullFile（兜底） |
| 6 | WPS PDF 文档 | .pdfwpsshellnew | Command |
| 7 | PPT 演示文稿 | .ppt | NullFile（兜底） |
| 8 | PPTX 演示文稿 | .pptx | NullFile（兜底） |
| 9 | WPS AI 生成 PPT | .pptxwpsaicreateshellnew | Command |
| 10 | WinRAR 压缩文件 | .rar | FileName |
| 11 | RTF 文件 | .rtf | NullFile（兜底） |
| 12 | 文本文档 | .txt | NullFile（系统内置项） |
| 13 | XLS 工作表 | .xls | NullFile（兜底） |
| 14 | XLSX 工作表 | .xlsx | NullFile（兜底） |
| 15 | WinRAR ZIP 压缩文件 | .zip | FileName |

规则细节：

- 排序：文件夹、快捷方式固定前二，其余按扩展名字母序（系统就是这么排的）。
- 显示名优先级：`MenuText`（`SHLoadIndirectString` 解析 `@shell32.dll,-30318`）→
  ShellNew 默认值 → 扩展名登记的 ProgID 的友好类型名（`AssocQueryString`）→
  按扩展名问系统 → 系统类型名 → 键名。
- 图标优先级：`IconPath`（`SHDefExtractIconW` 取 16px）→ 模板文件图标 →
  系统文件夹图标 → 扩展名图标 → ProgID 的 `DefaultIcon`。
- 过滤：处理器缺失的项（`.library-ms`）、命令里的程序已不存在的项（`.contact` 指向
  已卸载的 `Wab.exe`）不显示，系统菜单同样不显示它们。
- 「快捷方式」：`.lnk` 的 ShellNew 是 Handler + NullFile，直接建空文件是坏文件，
  改为走系统自己的「新建快捷方式」向导：拿目录背景的 `IShellFolder` →
  `IContextMenu` → `QueryContextMenu` → `IContextMenu2::HandleMenuMsg(WM_INITMENUPOPUP)`
  填充「新建」子菜单 → 找到「快捷方式」那一项的命令号 → `InvokeCommand`。
  （`rundll32.exe appwiz.cpl,NewLinkHere` 在 Win10 实测无效，进程启动即退出。）
- 建完立刻 `InsertEntry` + 选中 + 进入改名；向导类创建完刷新目录。
- 一级菜单里另有「新建文件夹」（原来就有，保留），放在「新建」子菜单上方；
  新建后同样自动进入重命名。
- 清单在启动后由后台线程枚举一次，存内存；新装软件需重启程序才出现。

## 阶段 14：右键菜单按场景拆分（2026-11-15）

以前只有一套菜单，靠"有没有选中"给项置灰，结果空白处和文件/文件夹/多选
共用同一套：文件右键也出现「新建」、多选里还留着「重命名」、盘符能被重命名。

这一版先把场景判出来，再按场景拼菜单。判定只用内存里的条目数据
（`isFolder` / 路径前缀 `::` `shell:` / 选中数量 / 是不是根目录），
不读注册表、不调 COM、不探测文件，右键弹出仍然零成本。

| 场景 | 什么时候 | 菜单项 |
| --- | --- | --- |
| 空白处 | 没选中任何项 | 查看 / 粘贴（剪贴板有文件才出现）/ 新建文件夹 / 新建 / 刷新 / 属性 |
| 单文件 | 只选中一个普通文件 | 打开 / 打开方式（账本里有程序才出现）/ 剪切 / 复制 / 删除 / 重命名 / 属性 |
| 单文件夹 | 只选中一个文件夹 | 打开 / 在新窗口中打开 / 剪切 / 复制 / 删除 / 重命名 / 属性 |
| 多选 | 选中 2 个以上 | 打开 / 剪切 / 复制 / 删除 / 属性 |
| 盘符或虚拟项 | 盘符根目录、`::`、`shell:` 项 | 打开 / 在新窗口中打开 / 属性 |
| 组标题 / 分隔行 | 点在这两种行上 | 不弹菜单 |

分隔线分组照资源管理器：空白处是「查看 ┃ 粘贴 ┃ 新建 ┃ 刷新 ┃ 属性」，
单文件是「打开、打开方式 ┃ 剪切、复制 ┃ 删除 ┃ 重命名 ┃ 属性」。

按用户要求去掉的项：「创建快捷方式」「发送到」「排序方式」。
（这三项系统里有，但日常用不上，留着只占宽度。）

- **多选属性**：以前只弹第一个选中项的属性。现在多选时把选中的对象装进一个
  `IDataObject`（`SHParseDisplayName` 求 PIDL → `SHCreateDataObject`），
  再交给 `SHMultiFileProperties` 弹系统的「多个项目属性」窗口
  （顶部显示"N 个文件"、有"计算大小"、第二页能改公共属性）。
  PIDL 组不起来（选了虚拟项）时退回第一个的属性。
- **在新窗口中打开**：再启动一个自身进程，把目录当命令行参数传过去。
  `main.cpp` 新增 `ExtractStartupPath` 解析 `lpCmdLine`（去空白、去成对引号），
  `MainWindow::Create(hInstance, initialPath)` 接受初始目录；
  WM_CREATE 里"命令行目录可用就用它，否则按上次停的目录"。两个窗口互不影响。
