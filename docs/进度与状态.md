## 本轮追加（2026-11-15）：系统项图标、虚拟项打开、程序图标

### ① 主文件夹 / 控制面板 / 回收站等系统项图标显示成黄色文件夹

- 原因：`SHGetFileInfo` 的**字符串**接口不认 `::{GUID}` 这种系统节点名，一律返回 0；
  代码又把 0 当成"没取到"，退回普通文件夹图标。详见踩坑记录「坑 25」。
- 修法：`ShellIcon.cpp` 的 `GetIconIndexByFullPath` 里判 `::` / `shell:` 前缀，
  先用 `SHParseDisplayName` 换成 PIDL，再用 `SHGFI_PIDL | SHGFI_SYSICONINDEX | SHGFI_SMALLICON` 查，
  结果照旧写 `m_pathIconCache`。
- 实测 iIcon：主文件夹 72 / 控制面板 21 / 回收站 32 / 网络 17 / 此电脑 15 / 桌面 74 / 库 295。

### ② 控制面板里的项双击打不开功能

- 原因：这些项（BitLocker、恢复、安全和维护、凭据管理器…）属性上带 `SFGAO_FOLDER`，
  程序当成文件夹往里导航，而它们其实是 applet，进去只有一个空列表。
- 修法：新增 `shell::ShellItemIsContainer()`，探测它能不能真的绑定出 `IShellFolder` 并 `EnumObjects`；
  `MainWnd::OnItemActivated` 里：容器 → 导航（空目录也进），非容器 → 交给系统打开。
  详见踩坑记录「坑 26」。
- 实测：双击 BitLocker → 弹出系统界面；回收站 → 进入 647 项；控制面板 9 项 → 所有控制面板项 39 项。

### ③ 程序 exe 和标题栏没有图标

- 新增 `res/app.ico`（16/32/48/256 四尺寸 PNG-in-ICO）、`res/resource.h`（`IDI_APPICON 101`）；
  `res/app.rc` 加 `IDI_APPICON ICON "app.ico"`；`MainWnd.cpp` 窗口类的 `hIcon` / `hIconSm` 改用它，
  取不到才退回 `IDI_APPLICATION`。
- 实测：exe 文件图标、标题栏左上角、任务栏都显示新图标。

### ④ 顺带修：回收站等顶层项的「向上」落到了物理桌面

- 回收站的系统父项是 `C:\Users\kf168\Desktop`（物理桌面目录），点向上会掉进"只有桌面文件"的 33 项；
  资源管理器里应该回到那个装着「此电脑/主文件夹/音乐…」的「桌面」容器（51 项）。
- 修法：`ShellFolder.cpp` 新增 `IsPhysicalDesktopPath()`，`GetParentPath()` 里把物理桌面换成顶层容器伪路径。
  详见踩坑记录「坑 27」。

### 阶段 5：文件操作改后台执行 + 右键菜单

**一、大文件复制不再卡界面**

原来粘贴/删除是在界面线程里等系统搬完，复制 1G 文件的那几秒钟整个窗口不能操作。
现在把整个操作放到一条后台线程里跑：

- 后台线程自己初始化 COM（每个线程独立，不能借用主线程的）
- 系统进度框照样弹，点「取消」照样管用
- 操作结束后线程往主窗口发一条消息，主窗口重新扫当前目录刷新
- 同一时间只允许一个文件操作，避免两个进度框打架
- 关闭窗口时会等后台操作收尾（用户也可以在进度框里点取消让它提前结束）

**实测数据**（复制 1GB 文件到子目录，C 盘内）：

| 指标 | 结果 |
|---|---|
| 复制耗时 | 2.9 秒（1GB） |
| 复制期间主窗口响应 | 每次探测 1～20 ms，**没有一次卡住** |
| 完成后 | 自动刷新，列表显示 1 项 ✅ |

> 对照：改造前同样的探测会超时（主窗口被同步调用占住）。

**二、右键菜单**

在文件列表上按右键弹出，和资源管理器同样的位置、同样的操作：

### 阶段 6：表头排序、F2 重命名、刷新不再整屏重建

**一、点表头排序**

点「名称 / 修改日期 / 类型 / 大小」任意一列表头，就按那列排：

- 第一次点 = 升序（小到大），再点同一列 = 降序，交替
- 换一列就从升序开始
- 表头上会有系统自带的小三角箭头 ▲ / ▼，不用自己画
- **文件夹永远排在最前面**，这条不受点哪一列影响（和资源管理器一致）
- 排序后滚动位置和选中项都保留

**二、F2 重命名**

选中一项按 F2（或在右键菜单里点「重命名」），名字原地变成可编辑框：

- 直接改，回车确认，Esc 取消
- 名字没变就不做任何操作
- 名字里有 `\ / : * ? " < > |` 这些非法字符，自己先挡掉，不弹系统的英文报错框
- 改名成功后只更新这一行，不重扫目录
- 和系统一样的冲突处理（目标已存在同名会弹系统的询问框）

**三、删掉「整屏刷新」这个毛病**

原来的做法：删除/新建之后，把整个目录重新枚举一遍，然后清空列表重新填，
结果就是**选中丢了、滚动位置回到顶部、屏幕闪一下**。

现在的做法分两种：

| 操作 | 以前 | 现在 |
|---|---|---|
| 删除 | 重扫整个目录 + 重建列表 | **直接从列表里摘掉删掉的那几行**，0 毫秒，不闪 |
| 新建文件夹 | 重扫整个目录 + 重建列表 | **往列表里插一行**并选中它，0 毫秒，不闪 |
| 复制/移动粘贴 | 重扫整个目录 + 重建列表 | 仍要重扫（新增多少项、名字会不会变成「xxx - 副本」事先不知道），但**保留滚动位置和选中项，且不擦背景不闪白** |

重扫时保留状态的实现：刷新前记下「选中了哪些名字」「顶部是哪一行」，
数据换完之后按名字把它们找回来，所以用户不会感觉列表被"重置"了。

### 阶段 7：剪贴板与系统互通

**原来什么毛病**：剪贴板只记在自己程序内存里。
从资源管理器复制的文件，在本程序按 Ctrl+V 粘不进来；
在本程序复制的文件，到资源管理器里也粘不出来。

**现在怎么做**：改用 Windows 的标准剪贴板格式。

| 格式 | 作用 |
|---|---|
| `CF_HDROP` | 一堆文件路径。资源管理器、桌面、别的程序都认这个格式 |
| `Preferred DropEffect` | 一个数字：1 = 复制，2 = 剪切。没有它接收方一律当复制处理，Ctrl+X 就失效 |

- Ctrl+C 往剪贴板写 `CF_HDROP` + 效果 1（复制）
- Ctrl+X 往剪贴板写 `CF_HDROP` + 效果 2（剪切）
- Ctrl+V **每次都从系统剪贴板读**（不是读自己内存里记的），所以从哪儿复制来的都能粘
- 剪切粘贴成功后把剪贴板清空（和资源管理器行为一致）

**几个容易翻车的细节**：

1. `SetClipboardData` 成功之后，那块内存就归系统了，**绝对不能再 `GlobalFree`**，
   否则程序直接崩。只有失败时才需要自己释放。
2. `GetClipboardData` 拿到的内存只有到 `CloseClipboard` 之前有效，
   所有字符串必须在关闭剪贴板之前复制出来。
3. 剪贴板同一时间只能被一个程序占用，遇到占用要重试（我们重试 10 次，每次隔 50ms）。

**问题 1：被剪切的文件要变色（和资源管理器一样）**

**问题 2：文件被剪切走了，源目录还显示着它**

移动完成后遍历本次操作涉及的路径，凡是父目录等于当前目录的，直接从列表里摘掉
（`RemoveItemByPath`），不重扫。

实测：本来的场景（剪切 → 进子目录 → 粘贴 → 回源目录）其实不会残留，
这条属于保险性修复，一并做了。

**问题 3：删除、复制会整表刷新，新建文件夹又不刷新——统一成"不整表刷新"**

核心是 `FileListView::MergeResult`：拿到新枚举结果后，逐行比对 `fullPath`，
找到第一个不同的位置 `common`：

- 全等 → 直接返回，一个像素都不重绘
- 有差异 → `SetItemCountEx` 新数量 → 还原选中和滚动 → `ListView_RedrawItems(common, count-1)`

另外两处必须同时改，否则会"先空再满"：

1. `StartEnumeration` 不再无条件 `SetResult(nullptr)`，只有**目标目录 ≠ 当前显示目录**时才清空
2. `RestoreSelectionAndScroll` 先 `LVM_SETITEMSTATE(-1, 0)` 清空所有选中再按名字恢复
   （否则"选中的行号"会粘到新内容上，等于选错了东西）

粘贴完成后用 `AllPaths()` 求差集 + `SelectPaths()` 把新出现的项选中，和资源管理器一致。

`OnEnumerationDone` 和 `OnColumnClick` 都改成走 `MergeResult`。

### 阶段 9.5：拖到子文件夹 + 外部改动自动刷新（你提的两个问题）

**问题 1：拖到列表里"新建文件夹"这种文件夹上没反应**

原来列表的落点永远是"当前目录"，拖到文件夹图标上也不会进那个文件夹。

改成两级判断：

1. 鼠标压在这一行上（整行都算，压在其他列上也认），**且这一行是文件夹** →
   落点 = 这个文件夹的完整路径
2. 压在文件行上 / 压空白处 → 落点 = 当前目录

视觉反馈：用系统自带的拖放高亮（`LVIS_DROPHILITED`）把鼠标正压着的那一行点亮，
和资源管理器一致；鼠标离开列表或放完自动清掉。

**问题 2：文件被移走 / 删除后列表不自己更新（本程序内部、资源管理器外部都不刷）**

根因：以前只有"本程序自己做文件操作"结束时才刷新一次，
别的程序动过的文件，本程序完全不知道。

新增 `src/core/FolderWatcher.*`：用系统的 `ReadDirectoryChangesW`
盯着当前目录，一有变化就通知主窗口。

三道保护，保证它不会拖慢速度、也不会打断用户：

| 保护 | 做法 | 解决什么 |
|---|---|---|
| 独立线程等待 | 监视放后台线程，没变化时完全睡着，不占 CPU | 不在界面线程做阻塞调用，窗口不卡 |
| 通知合并（防抖） | 收到通知只排一个 250ms 定时器，反复重置；动静停了才真正刷一次 | 批量复制一万个文件时不会把界面刷成幻灯片 |
| 冲突退让 | 文件操作进行中 / 正在 F2 改名，这一轮直接跳过 | 刷新不会打断正在进行的操作和输入 |

刷新本身走的是已有的**差异更新**路径（`MergeResult`），
只重绘真正变了的那几行，不会整表重建。

### 3. 控制面板项双击打不开（已修复，实测通过）
根因有两层：
1. 这类项的解析名是「父项 + \0\ + 显示名」（如 `::{26EE0668-…}\0\字体`），

2. 换成 `IShellItem → BHID_SFUIObject → IContextMenu → InvokeCommand` 也不行：

   都回 `E_INVALIDARG(0x80070057)`。

改法：**把枚举时的绝对 PIDL 存进 ShellEntry**（纯字节，不含 COM 指针，符合跨线程约定），
打开时用 `ShellExecuteExW` + `SEE_MASK_IDLIST | SEE_MASK_INVOKEIDLIST` 执行默认动词。
- `ShellEntry` 新增 `std::vector<unsigned char> pidl`，只在 Shell 命名空间目录里填
  （物理目录的条目用 fullPath 就够，省掉每项一次 PIDL 拼接）。
- 新增 `shell::OpenShellItemByPidl(HWND, pidlBytes)`；
  `MainWnd::OnItemActivated` 两个分支都改成「先 PIDL → 再路径字符串 → 最后 ShellExecuteW」。
- 实测：双击「字体」打开系统「设置」；双击「恢复」弹出控制面板恢复页；

  主文件夹 / 顶层桌面这些系统文件夹 → 小图标。用户从「查看」菜单手动选过之后
  不再自动改（`m_viewModeManual`）。
- 入口：右键菜单新增「查看」子菜单，四种视图单选、当前项打勾。
- 实测：此电脑默认小图标；四种视图来回切换显示正常。

### 5. 「此电脑」分组（按方案 A 实现，已实测通过）
- 系统里「此电脑」是分组显示的（组名「设备和驱动器」）。列表控件的原生分组
  （`LVM_ENABLEGROUPVIEW`）在虚拟模式（`LVS_OWNERDATA`）下不可用，
  所以按方案 A 改成「在数据里插一行假标题、自己画成标题」：
  - `ShellEntry` 加 `bool isGroupHeader`（不是真文件：不能双击、不能选中、不能改名、
    没有图标和日期大小）。
  - `MainWnd::OnEnumerationDone` 在**排序之后、SetResult 之前**插入标题行，
    并且先判第 0 行是否已有标题行——同一份结果被处理两次也不会插成两行。
  - `FileListView`：
    - `LVN_GETDISPINFO` 对标题行只给名字，`iImage = I_IMAGENONE`；
    - `NM_CUSTOMDRAW` 整行自绘：白底、深灰字、字号比正文小一号、左边缩进 6px；
    - `LVN_ITEMCHANGING` 拒绝标题行被选中（单击、Ctrl+A 全选都选不上）；
    - `LVN_BEGINLABELEDIT` 拒绝标题行进入改名。
  - 标题、状态栏的「N 项」要把标题行减掉（新增 `MainWindow::RealItemCount`），
    否则「此电脑」会显示成 7 项。
  - `SortEntries` 排序时跳过开头那段标题行，排完再接回去。
- 「此电脑」里**禁用按列排序**：`OnColumnClick` 判断当前目录是此电脑就直接返回
  （一排序标题行就会被当成普通条目排到中间，分组就散了；系统的此电脑本来也不让排序）。
- 实测：此电脑显示「设备和驱动器」标题 + 6 个盘，计数 6 项；连按两次 F5 标题仍是一行；
  单击标题行没有选中效果；点表头「名称」顺序不变；进 C 盘无标题行、排序正常。
### 6. 「此电脑」平铺视图（已实测通过）
系统的此电脑除了分组，每个磁盘还是一块「平铺」：左边图标，右边磁盘名，
名字下面一行容量（「14.1 GB 可用，共 125.9 GB」），再下面一条占用进度条。

- 数据：`ShellEntry` 新增 `driveType / diskFree / diskTotal`（网络盘也查容量，系统此电脑同样显示），
  在枚举线程里用 `GetDriveTypeW` + `GetDiskFreeSpaceExW` 填。

- 视图：新增 `ViewMode::Tiles`。Windows 自己的平铺视图（`LVIF_TILEINFO`）在
  虚拟模式下不生效，所以这里用「`LVS_ICON` + 格子宽度等于列表宽度」实现
  **一行一个**，再整格自绘（`DrawTile`）：
  - 48px 图标在左，名称一行，容量一行，进度条一条（轨道浅灰、已用蓝、超 90% 变红）
  - 每块卡片固定 300 宽、68 高，一行按窗口宽度并排几块（窗口拉宽就多排几块）
  - 选中判断用 `ListView_GetItemState(LVIS_SELECTED)`；
    `nmcd.uItemState` 里的位在 owner-data 下不可靠（踩过：6 个格子全被画成蓝底）
- 分组改成两组：`DRIVE_REMOTE` 归「网络位置」，其余本地盘/光驱/U 盘归「设备和驱动器」；
  网络位置为空时不插第二个标题，免得出现空组。
- 此电脑默认视图 = 平铺；右键「查看」里也加了「平铺」这一项。
- 实测：此电脑显示「设备和驱动器」+「网络位置」两个标题；C 盘显示容量和 89% 进度条，
  DVD 0 GB 可用显示成红条；单击一行只有那一行变蓝；计数 6 项。
- 分组标题要「独占一整行」，但列表控件没法让某一格跨行，所以在标题后面补几个「空占位格」（ShellEntry::isSpacer）把这一行剩下的位置填满，磁盘就从下一行开始；组末尾同理补余数，下一组标题才不会挤上来。占位格不显示内容、不能被选中、双击无反应、也不计入「共 N 项」。
### 7. 「主文件夹」排序：系统项在前、桌面上的东西在后

现象：主文件夹（顶层桌面，51 项）原来全部按名字混排，
「此电脑」「回收站」「控制面板」「库」这些散落在一堆桌面文件中间。

改法：
1. `ShellEntry` 加 `isSystemItem`，枚举时由 `IsDesktopSystemItem` 判定：
   - 路径为空、或形如 `::{GUID}` → 系统项（虚拟项）
   - 路径落在桌面目录 / 公用桌面目录「之下」→ 桌面上的东西
   - 路径正好等于桌面目录本身（即「桌面」这个系统入口）→ 系统项
   - 其余（驱动器、用户目录、OneDrive、KnownFolder 入口）→ 系统项
   桌面目录用 `FOLDERID_Desktop` / `FOLDERID_PublicDesktop` 现查并缓存，
   用户把桌面搬到别处也能判对。
2. `CompareEntries` 最前面加一条：`isSystemItem` 不同时，系统项在前。
   这一条不受"点哪一列排序"影响，其余规则（文件夹优先 → 列 → 名字）不变。

实测：17 个系统项在前（DVD 驱动器、M W、OneDrive、此电脑、回收站、控制面板、库、视频、
图库、图片、网络、文档、下载、音乐、主文件夹、桌面），34 个桌面项在后，
组内仍是文件夹优先 + `StrCmpLogicalW` 名称序。
### 8. 去掉「幽灵控制面板」；系统目录的地址栏名字与「向上」

**8.1 列表里不再有两个「控制面板」**

顶层桌面枚举出两个都叫「控制面板」的项：
- `::{26EE0668-A00A-44D7-9371-BEB064C98683}` —— 真能用的那个（9 项首页），保留；
- `::{5399E694-6CE5-4D6C-8FCE-1D8870FDCBA0}` —— 连系统自己都打不开
  （`Shell.Application.NameSpace` 直接报「找不到元素 0x80070490」），没有图标、双击没反应。
在枚举阶段直接跳过第二个，列表里只剩系统那个。主文件夹从 51 项变成 50 项。

**8.2 从「主文件夹」点进「文档」，地址栏写「文档」、向上回「主文件夹」**

系统资源管理器记的是"从哪儿点进来的"，不是纯路径。照这个做：

1. `MainWindow` 加 `m_navOrigins`（小写路径 → { 显示名, 上一级 }）。
   只有**在列表里双击进入**时写一条（`RecordNavigationOrigin`），
   记下 `entry.name`（「文档」）和进来之前待着的目录（「主文件夹」）。
   地址栏输入、左栏点击、后退/前进都不写，所以"从 C:\Users\kf168 点进 Documents"
   仍然显示真实路径、向上回 C:\Users\kf168，两者互不干扰。
2. 地址栏/标题统一走 `DisplayNameFor(path)`：有来源记录就用记录的名字，否则按路径推导。
3. `AddressBar::SetPathWithLabel` 加第三个参数 `wholeLabel`：名字和路径不一样时，
   地址栏整条只画这一个名字（不切成 `C: > Users > kf168 > Documents`），
   点击它照旧跳到该路径。
   同时 `AddressBar::SetPath` 里"普通路径清空 label"的逻辑要放过这种整条 label 模式，
   否则名字刚设上就被清掉（踩了一次）。
4. `GoUp` 先查来源表：有记录就回记录的上一级，没有才走 `shell::GetParentPath`。

实测：
- 主文件夹双击「文档」→ 标题「文件管理器 - 文档（5 项）」、地址栏整条「文档」；
- 点向上 → 回「主文件夹（50 项）」、地址栏「主文件夹」。
### 9. 左侧导航条「常用位置」也算"主文件夹下的入口"

现象：从左侧点「文档」「下载」「图片」这些，地址栏显示 `C: > Users > kf168 > Documents`
这样的真实分段路径，向上也回 `C:\Users\kf168`，跟从「主文件夹」双击进去不一致。

改法：
1. `shell::KnownFolderDisplayName(path, name)`：把路径和
   桌面 / 下载 / 文档 / 图片 / 音乐 / 视频 六个 KnownFolder 现查的路径逐一比对，
   命中就向系统要它的显示名（`SIGDN_NORMALDISPLAY`，多语言也正确）。
2. `MainWindow::OpenPinnedOrFolder`（左栏点击的统一入口）在目录分支里先问一次：
   命中就把来源记成「显示名 + 上一级=主文件夹」，再导航。
   `RecordNavigationOrigin` 因此多了一个可选参数 `parentPath`：
   留空 = 上一级取"进来之前待着的目录"（列表双击走这条），
   传值 = 用它（左栏常用位置固定回主文件夹）。
3. 地址栏整条显示名字、`GoUp` 先查来源表，这两条沿用第 8 节已有的逻辑，不用改。

实测（起点故意选在「此电脑」，不选主文件夹）：
- 左栏点「文档」→ 标题「文件管理器 - 文档（5 项）」、地址栏「文档」；
- 点向上 → 回「主文件夹（50 项）」，不是 C:\Users\kf168。
